## 1️⃣ 双击后窗口一闪就没

**原因**：脚本还没跑到"暂停"就退出了，或启动器被当成管道调用导致退出码失真。

**做法**：改用 `CampusNet_Debug.bat` 启动：它加了 `-NoExit`，窗口不关，报错直接看得见。

**还不行**：打开 `logs\<今天>\CampusNet_Launcher.log`，看最后几行。
启动器现在**无论成败都会停住**并显示 `Press any key to close this window...`，所以正常情况下不该再闪退。

---

## 2️⃣ 网络类：没网卡 / 只有 169.254 / 插网线没反应

这三种通常是同一件事：**网卡没拿到 DHCP 租约**，只剩 `169.254.x.x` 这种自分配地址。

### 免重启修复：主菜单 `6`（或 `-Repair`）

```powershell
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -Repair
```

**三步**：

| 步骤 | 做什么                                                      | 需要管理员？ |
|:---- |:----------------------------------------------------------- |:------------ |
| 1    | 清 DNS 缓存（仅当 `FlushDnsOnRepair=1`）+ 清 ARP / 邻居缓存 | 清 ARP 需要  |
| 2    | 对"链路已连但没租约"的网卡做 Release → Renew DHCP           | 不需要       |
| 3    | 仍不可用时重启网卡（等价于重启后重新初始化驱动）            | **需要**     |

- 修复过程会**逐条打印它做了什么**（含每一步被跳过的原因），事后可在 `logs\<日期>\CampusNet_Log.txt` 回看；
- **没有管理员时**：跳过"清 ARP"与"重启网卡"两步，DNS 清理（若开启）与 DHCP 重新申请照常执行；
- 想以管理员运行：右键 `CampusNet.bat` → 以管理员身份运行；
- 退出码 `5` = **修复未完成**（仍有物理网卡不可用）。

> ⚠️ 三步做完还是不行，**多半不是本机问题**，而是网络侧没放行 DHCP（端口/MAC 绑定、需重新认证，或该口不在校园网）。
> 换个网口、等几分钟，或找学校网络中心。

**想看每张网卡为什么被排除**：跑诊断（见 §8）。

## 3️⃣ 账号类：密码错 / 已在别处登录 / 解密失败

| 提示                                                      | 什么原因                                                                 | 怎么办                                                                                     |
|:--------------------------------------------------------- |:------------------------------------------------------------------------ |:------------------------------------------------------------------------------------------ |
| `密码错误`、`ret_code:1/3/4`                              | 账号或密码不对                                                           | 核对后重跑 `FirstTimeSetup.bat`；若刚改过密码必须重跑                                      |
| `本终端已经在网`、`ret_code:2`、`AC999`、`终端IP已经在线` | 门户原文是「终端IP已经在线」，即**本机已经在网**                         | 若确实上不了网，再去自助服务看有无历史会话占着：`http://10.0.8.81:8080/Self/login/?302=LI` |
| `密码解密失败：配置可能来自其他 Windows 用户或另一台电脑` | 密码用 DPAPI 加密，绑定"本机 + 当前用户"，换电脑/换用户/重装系统都解不开 | 删掉 `CampusNet_Config.json`，重跑 `FirstTimeSetup.bat`                                    |
| `配置缺少账号或密码`                                      | 配置里的账号或密码为空                                                   | 同上                                                                                       |
| `检测到旧版 Base64 密码，正在迁移为 DPAPI 加密`           | 老版本用可逆 Base64                                                      | **正常现象**，自动迁移，不用管                                                             |

**换电脑 / 多人共用一台电脑**：重跑 `FirstTimeSetup.bat` 输入新账号，旧配置会被覆盖。

> 💡 这类错误**不会**弹浏览器：脚本判断"开浏览器也帮不上忙"（见 §4 的分流表）。

## 4️⃣ "伪登录"：提示成功却上不了网

脚本**不信服务器说的"成功"**：登录接口返回成功后，还会真的下载一次 **HTTPS 网页内容**来确认能不能上网
（校园网门户一般只劫持 HTTP，冒充不了 HTTPS 响应），所以被劫持的页面不会被误判成"已联网"。
**只有真实联网校验通过才算成功。**

**三条常见原因，依次排查**：

1. **账号已在别处登录** → 用手机打开校园网登录页，点「注销 / 下线」，再回电脑重试；
2. **Radius 认证失败 / 超时**（`ret_code:7`/`8`） → 通常是 AC 与 RADIUS 侧的问题：`Win+R` 输入 `cmd`，执行 `ipconfig /release` 再 `ipconfig /renew`，然后重登；仍不行请联系网络中心；
3. **连错了网络**（比如连到手机热点） → 切回校园网 / 校园 Wi-Fi 再试。

**想看脚本到底收到了什么**：跑**登录联调**：

```powershell
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -TestLogin
```

它会打印**脱敏后的登录地址**（账号密码显示为 `***`）与**服务器原始响应**，再跑一次真实联网校验并明确点出"伪登录"。

### 登录失败时到底会不会弹浏览器？

| 失败类型                                      | 行为                                                         |
|:--------------------------------------------- |:------------------------------------------------------------ |
| 门户明确拒绝（`ret_code` 1、3、4、11） | **不弹**，提示重跑向导或去自助服务                           |
| 本终端已在线（`ret_code` 2）                  | **不弹**，提示若确实上不了网，再去自助服务看有无历史会话占着 |
| 协议 / 网络类失败、伪登录                     | 打开门户页兜底，手动确认一次即可上网                             |

想彻底关掉：配置 `Settings` 里加 `"OpenPortalOnFailure": "0"`。**静默模式永远不弹窗。**

## 5️⃣ 能上 QQ、打不开网页（DNS）

这是"域名解析"问题，不是登录问题。

**做法**：主菜单 `7`（或命令行 `-FlushDns`）：

```powershell
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -FlushDns
```

- 只清**本机 DNS 客户端缓存**：不改网卡、不碰登录配置、**不需要管理员**；
- **独立功能**：不会因为执行了"网络修复"就顺手跑一遍（想联动：配置 `"FlushDnsOnRepair": "1"`）；
- 会报告清理前后条数；**本机读不到条数时只说"指令已执行"，不编造统计**；
- 退出码 `0` 成功 / `6` 失败（失败多半是权限问题）。

## 6️⃣ 想开机自动登录

1. `Win+R` 输入 `taskschd.msc` 打开任务计划；
2. 新建基本任务：名称自取；触发器选「计算机启动时」或「计算机登录时」；操作选「启动程序」；
3. 「程序或脚本」填 `powershell.exe`；
4. 「添加参数」填 `-NoProfile -ExecutionPolicy Bypass -File "<本目录>\CampusNet_Silent.ps1"`；
5. 完成。

> ⚠️ **`CampusNet.bat` 不适用于本场景**：它是交互版，每次开机都会弹窗并一直等待按键。
> 静默版 `CampusNet_Silent.ps1` 无窗口，结果用退出码表示（0 成功 / 4 失败），默认还会等网卡最多 60 秒。

## 7️⃣ 日志：在哪、看哪个

**统一在 `CampusNet_AutoLogin\logs\<日期>\`**（例如 `logs\2026-09-28\`）：每天一个文件夹、最多 4 个文件。
启动时会自动建当天目录，并按保留天数清理旧目录（默认 30 天；**当天与未来永不删**）。
启动时屏幕会打印一行「日志目录：<完整路径>」。

| 出什么情况                       | 看哪个                                           |
|:-------------------------------- |:------------------------------------------------ |
| 这次运行到底打印了什么（交互版） | `CampusNet_Launcher.log`（每次运行覆盖）         |
| 开机自启 / 计划任务出问题        | `CampusNet_Silent.log`                           |
| 历史上每次登录成没成             | `CampusNet_Log.txt`（**追加**；超 1MB 截断一半） |
| 脚本崩了（异常、调用栈）         | `CampusNet_Fatal.log`（仅崩溃时生成）            |

改存放位置或保留天数：配置 `Settings` 里的 `"LogDir"`（默认 `"logs"`）与 `"LogRetentionDays"`（默认 `"30"`，`"0"` = 永不清理）。

## 8️⃣ 命令速查 + 退出码

```powershell
# 网络体检：全量网卡（含每张被排除的原因）+ 是否真能上网 + 门户探测
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -Diagnose

# 登录联调：脱敏登录 URL + 服务器原始响应 + 真实联网校验   ← 排查"伪登录"首选
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -TestLogin

# 免重启网络修复（清缓存 → 重拿 DHCP → 必要时重启网卡；后两项之外见 §2）
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -Repair

# 只清 DNS 缓存（独立功能，不与"网络修复"混在一起）
powershell -ExecutionPolicy Bypass -File .\CampusNet_Login.ps1 -FlushDns

# 静默登录并查看退出码
powershell -ExecutionPolicy Bypass -File .\CampusNet_Silent.ps1 ; echo $LASTEXITCODE
```

| 开关         | 作用             | 退出码              |
|:------------ |:---------------- |:------------------- |
| `-Setup`     | 只跑首次设置向导 | `0` 成功 / `1` 失败 |
| `-Silent`    | 静默登录         | 透传 `0`-`4`        |
| `-Diagnose`  | 网络诊断         | 恒 `0`              |
| `-TestLogin` | 登录联调         | 恒 `0`              |
| `-Repair`    | 免重启网络修复   | `0` / `5`           |
| `-FlushDns`  | 只清 DNS 缓存    | `0` / `6`           |

| 退出码 | 含义                                                                                        |
|:------ |:------------------------------------------------------------------------------------------- |
| `0`    | 成功 / 当前已在线                                                                           |
| `1`    | 没有配置文件（跑 `FirstTimeSetup.bat`）；脚本抛未捕获异常也是 1（看 `CampusNet_Fatal.log`） |
| `2`    | 配置文件损坏（解析 / 解密失败、字段缺失）→ 重跑向导                                         |
| `3`    | 没有可用网卡（已按 `-AdapterWaitSec` 等待过）→ 跑 `-Diagnose` 看每张卡的原因                |
| `4`    | 登录失败（含"伪登录"）                                                                      |
| `5`    | `-Repair` **修复未完成**（仍有物理网卡不可用）                                                             |
| `6`    | `-FlushDns` 清理失败（多半是权限问题）                                                      |

## 9️⃣ 完全不能用 / 怎么求助

1. **手工登录**：浏览器打开门户页 `http://10.0.10.252/`，能上网就说明脚本的问题可以慢慢查；

3. **求助时请附上**：`logs\<今天>\CampusNet_Launcher.log` 全文 + 退出码 + `-TestLogin` 的输出发送到 issue
   + 一句话说明"做了什么、看到了什么"。

## 附录 B · 错误自检与排错


> README 六章的“30 秒定位”仍不能解决问题时，这里给出全部细节。

### B.1 提示语 → 原因 → 怎么办

| 现象 | 什么原因 | 怎么办 |
|:------------ |:-------- |:------ |
| 窗口一闪而过，什么都没发生 | 老版启动器的 `%errorlevel%` 在解析期就被展开，`pause` 从没执行到 | 已修：现在**无论成败都会停住**；若仍闪，用 `CampusNet_Debug.bat` |
| `密码解密失败：配置可能来自其他 Windows 用户或另一台电脑` | DPAPI 密文绑定"本机 + 当前用户"，换电脑 / 换用户 / 重装系统后解不开 | 删掉 `CampusNet_Config.json`，重跑 `FirstTimeSetup.bat` |
| `配置缺少账号或密码，请重新运行 FirstTimeSetup.bat` | 配置里的账号或密码为空 | 同上 |
| `检测到旧版 Base64 密码，正在迁移为 DPAPI 加密` | 老版本用的是可逆 Base64 | 正常现象，**自动迁移**，不用管 |
| `未找到具有有效 IPv4 地址的可用适配器。各网卡情况：` | 所有网卡都没有可用 IPv4 | 跑 `-Diagnose` 看原因；网线没插 / 没连 WiFi / 没拿到 DHCP |
| `提示：网卡只有 169.254.x.x（APIPA）表示没拿到 DHCP 租约…` | DHCP 租约没拿到，网卡停在自动私有地址 | 跑 `-Repair`（免重启修复） |
| `暂时没有可用网卡，等待网卡就绪（最多 N 秒）…` | 刚插网线 / 刚连 WiFi，系统还在拿 IP | 等它；静默版默认等 60 秒 |
| `无线网卡查不到当前 SSID（不一定代表没连上），继续尝试登录` | 无线驱动不报 SSID | 一般不用管，**只要拿到 IP 就会继续登录** |
| `门户探测到的 IP(...) 与网卡 IP(...) 不一致，以门户为准` | 网卡报的 IP 与门户看到的源 IP 不同（多网卡 / NAT） | 正常，脚本以门户为准 |
| `portal 自动发现：未探测到跳转（可能已联网或不在校园网内）` | 探针没被劫持 | 先确认是否已经能上网；不能就确认连的是校园网 |
| `门户判定请求参数非法（…）：XOR key 或参数形态不对，改走下一策略` | 参数混淆 key 算错或门户改了协议 | 多半是 `JsVersion` 等配置过期；跑 `-TestLogin` 看原始响应 |
| `portal 响应不可识别（HTTP 200）。原始响应预览：…` | 接口形态变了，返回的不是 JSONP | 看预览内容；若是一段 HTML 说明走错接口，可提 issue |
| `portal 拒绝登录请求：HTTP N` | 服务端拒绝（如 HTTP 500） | 看响应预览；换 `BaseURL` 或确认门户是否改版 |
| `网络异常，未取得服务器响应` | 网络不通 / 门户不可达 | 先 `-Diagnose` 确认链路与网关 |
| `伪登录：登录接口返回成功，但实际仍无法访问互联网。请检查：…` | 见本文件 §4️⃣「伪登录」 | 按那三条依次排查 |
| `没找到任何物理网卡，无法修复。` | 系统里没有物理网卡（全被禁用？） | 检查设备管理器 |
| `没有需要修复的物理网卡：已经有一张网卡拿到了有效 IPv4 与网关。` | 网络其实是好的 | **不是故障**，去排别的问题 |
| `「…」重启网卡后仍未拿到 IPv4。这通常不是本机问题…` | 网络侧没放行 DHCP | 换网口 / 等几分钟 / 找网络中心 |
| `「…」仍未拿到 IPv4。重启网卡需要管理员权限…` | 第 3 步需要管理员 | 右键 `CampusNet.bat` → 以管理员身份运行 |
| `DNS 缓存清理失败：…：该操作需要管理员权限…` | 权限不足 | 同上 |
| `✘ 服务器说成功，但实际仍上不了网（伪登录）。` | 见本文件 §4️⃣「伪登录」 | 按那三条依次排查 |
| `这是账号/密码类错误，打开浏览器也帮不上忙，所以这次不弹浏览器。` | 脚本按错误类型分流 | 重跑向导 / 去自助服务 |
| `本终端已经在网（无需重复登录）。` | `ret_code=2` | 去 `http://10.0.8.81:8080/Self/login/?302=LI` 看看有没有历史会话占着 |
| 提示「找不到文件」 | 文件被分到不同目录了 | 所有 `.bat` / `.ps1` 必须**在同一目录** |
| 中文显示成乱码 | 终端编码问题 | 用 `CampusNet.bat` 启动（它会先 `chcp 65001`） |

### B.2 门户返回的错误码速查

| `ret_code`  | 含义                         | 怎么办                                                             |
|:----------- |:---------------------------- |:------------------------------------------------------------------ |
| `1`         | **密码错误**                 | 核对密码；改过密码就重跑 `FirstTimeSetup.bat`                      |
| `2`         | 本终端已经在网（无需重复登录）       | 若确实上不了网，再去自助服务看有无历史会话占着：`http://10.0.8.81:8080/Self/login/?302=LI` |
| `3` / `4`   | 系统繁忙 / 账号或密码错误  | 核对学号与密码                                                     |
| `7` / `8`   | Radius 认证失败 / 超时                | AC 与 RADIUS 侧的问题：重连后再试；持续出现则联系网络中心    |
| `11`        | 其他错误           | 联系网络中心                                                       |
| 一大段 HTML | 响应不可识别（接口形态不对） | 多半没连校园网，或门户改了接口：跑 `-TestLogin` 看原始响应         |

## 附录 C · 技术原理


### 脚本做了什么

```
1. 找身份证：获取电脑的 MAC 地址（像身份证号）
2. 找门牌号：获取电脑的 IP 地址（像家庭住址）
3. 算暗号：  用 IP 推导一个 key，把参数逐个字符 XOR 成十六进制（门户要求的格式）
4. 打电话：  把学号、暗号化的密码、MAC、IP 发给学校门户
5. 等回信：  接收门户回复，解析 result / ret_code
6. 亲自确认：不信门户的"成功"，自己再上一次网验证（这一步才是真判据）
7. 开门：    确认真的能上网，才会报告"成功"
```

### 门户拓扑

| 项目                   | 值                                                                                           |
|:---------------------- |:-------------------------------------------------------------------------------------------- |
| 门户入口页（80）       | `http://10.0.10.252/a79.htm?wlanusermac=…&wlanuserip=…&wlanacip=…`                           |
| **登录接口（主路径）** | `http://10.0.10.252:803/eportal/portal/login`（Dr.COM 哆点 v4）                              |
| 取页面配置             | `http://10.0.10.252:803/eportal/portal/page/loadConfig`（取 `program_index` / `page_index`） |
| 旧接口（自动回退）     | `http://10.0.10.252:801/eportal/?c=Portal&a=login`                                           |

- 登录参数按门户要求做 **逐字符 XOR + 十六进制**混淆，**XOR 的 key 由本机 IP 推导**：
  `key = IP 字符串每个字符 ASCII 码的逐位异或`（取自门户自带 JS `a41.js` 的 `util.getkey(term.ip)`）。
  脚本按当前网卡 IP 现算：**写死 `0x20` 会在别的网段被门户判为「请求参数包含非法内容」**（真实踩过，已修）；
- 未认证时用 `http://9.9.9.9/` 等探针自动发现真实的 `wlanuserip` / `wlanacip`；
- 探针会**自动避开**门户下发的 `visit_blacklist`（`1.1.1.1`、`generate_204`、`www.msftncsi.com` 等：
  这些地址门户不劫持，拿来做探针永远不会跳转）；
- 据抓包分析（结论已归档到 [`技术资料.md`](../Campus%20Network%20source%20code/技术资料.md)）：**所有请求都是 GET、零 POST**；不需要 Cookie，只认 `Referer` + `User-Agent`。

### 为什么安全

1. **本地存储**：密码只存在本机；
2. **本机加密**：DPAPI 绑定当前 Windows 用户，换电脑 / 换用户解不开；
3. **只发必要信息**：只发送登录所需字段；
4. **不落明文**：上屏与写日志前，账号与密码统一被 `Get-MaskedUrl` 换成 `***`。
