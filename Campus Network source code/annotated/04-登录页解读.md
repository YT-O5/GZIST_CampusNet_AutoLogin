# 04 · 门户入口页 `a79.htm` 逐行解读

> **这份是什么**：门户登录入口页（`a79.htm`）里每个变量与跳转参数的逐行讲解。
> **适合谁读**：想知道"页面上的 MAC/IP 是怎么变成登录参数的"的人。
> **相关文档**：系列总览 [`README.md`](README.md) · 协议真值 [`../技术资料.md`](../技术资料.md) · 原始文件 [`../raw/a79.htm`](../raw/a79.htm)

- **来源文件**：`../raw/a79.htm`（原名里带抓包时的 `wlanusermac`/`wlanuserip`/`wlanacip`，
  已按脱敏要求改名为 `a79.htm`；文件内容未改动）
- **原始行号**：第 1-87 行（全文）
- **抓取 URL**：`http://10.0.10.252/a79.htm?wlanusermac=<MAC>&wlanuserip=<本机IP>&wlanacip=<AC的IP>`
：未认证时访问任意 http 站点会被重定向到这个 `a79.htm`（本门户的"上网登录页"）。
  （示例真值见 `../captures/README.md` 的抓包真值表。）

> 说明：`a79.htm` 本身**不含登录逻辑**，它只做两件事：① 由内核注入一批"会话变量"；
> ② 定义"哆点客户端参数"并加载 `a41.js` 去跑真正的门户前端（`page.run()`）。
> 下文逐行给出每行的含义；源码里读不到/未使用的，明确标注「源码未体现」。

## 四、"哆点参数" 与 **新加密接口** 的关系（重点）

| 维度 | 旧哆点参数（`a79.htm` 第 24-71 行） | 新接口（`a41.js`/`a40.js`，本项目走的） |
| --- | --- | --- |
| 端口 | `authloginport=801` | **803**（`epHTTPPort=803`，见 `a41.js` 第 7 行） |
| 路径 | `authloginpath='/eportal/?c=ACSetting&a=Login'` | `/eportal/portal/login` |
| 提交方式 | 表单字段 `DDDDD`/`upass`（即 `authuserfield`/`authpassfield`） | 参数 `user_account`/`user_password` 等（`a40.js` `login_portal`） |
| 参数编码 | 一般 URL 编码 | **XOR key + hex**（key 由客户端 IP 推导，见 01 解读） |
| 成功/失败判定 | 跳转到 `authsuccess`/`authfail` 标志页（`_3.htm`/`_2.htm`） | 响应体 `dr1003({"result":1,...})`（见 02 解读） |
| 调用者 | 哆点**原生客户端** / 旧式页面（`login_method=0` 的 `default_login`） | 新版 Web 门户前端（`login_method=1/9` 的 `login_portal`） |

**关系一句话**：`a79.htm` 里的"哆点参数"是门户保留的**旧 801 表单接口**的声明
（字段名 `DDDDD`/`upass`、端口 801、成功/失败标志页）；而本校园网实际生效的是
`a41.js` 驱动的**新 803 `eportal/portal/*` 接口 + XOR 混淆**。
两者是**并列的两代协议**：旧接口在本门户**不可用**（这正是本项目 README 记的
「旧接口（本门户不可用）`:801/eportal/?c=Portal&a=login`」），新接口才是能成功登录的那套。
`a40.js` 的 `default_login`（片段 B）就是"旧接口形态"的前端实现，它把 `DDDDD`/`upass`/`0MKKey`
等旧字段与新 `user_account`/`user_password` 一起准备，再统一交给 `portal_login` 发送。
