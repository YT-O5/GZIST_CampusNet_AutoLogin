## 🗑️ 现状：本目录已无抓包文件

5 份 `.har` 已全部删除（含原先入库的那份脱敏版）。原因是**隐私**：

门户对凭据与客户端标识只做了"逐字符 XOR 一个字节再转十六进制"的**编码，不是加密**：
给定会话的 XOR key 就能一键还原。所以抓包天然属于敏感资料：**即使把账号密码字段替换成
`REDACTED`，里面仍然留着本机 MAC、客户端 IP、校园 WiFi 名**这些能定位到个人的信息。

| 原文件（已删除）           | 介质 | XOR key | 原用途                                          |
|:-------------------------- |:---- |:------- |:----------------------------------------------- |
| `10.0.10.252-lan1.har`     | 有线 | `0x20`  | 完整会话，正确密码一次成功                      |
| `10.0.10.252-lan2.har`     | 有线 | `0x20`  | 最短的一份（2 条登录 + 4 条资源），先输错再输对 |
| `10.0.10.252-5G.har`       | WiFi | `0x29`  | 完整会话，先输错再输对                          |
| `10.0.10.252-2.4G.har`     | WiFi | `0x25`  | 完整会话，先输错再输对                          |
| `10.0.10.252-redacted.har` | 有线 | `0x20`  | 上一份的脱敏版（内容一致），曾随仓库入库        |

> ✅ **历史里的抓包也已清除**：本仓库过去提交过 `*-redacted.har`，现已重写 git 历史把它从
> **所有提交**中移除，并用“遍历对象库全部对象字节流”验证为 0 命中，因此可安全推送公开仓库。
> 但如果你**自己重抓**后提交过，那仍需重写历史才能清除。

## 📥 怎么自己重新抓一份

1. 浏览器按 `F12` → 切到 **Network**
2. 勾上 **Preserve log**（保留日志，否则跳转后记录会被清空）
3. 让浏览器走一遍**门户登录**（输错、输对各来一次更有价值：成对的失败/成功能互相印证）
4. 在请求列表里右键任意一条 → **Save all as HAR with content**

> 🔒 **抓到之后请不要提交进仓库**。`.gitignore` 已排除 `*.har`，本目录也只为放这些文件而存在。
> 需要拿给别人看时，先按下面这份清单处理，或者干脆只贴**单个请求的参数表**（去掉值）。

**脱敏清单（别只盯着账号密码）**

| 字段                                                | 为什么要处理                                                                       |
|:--------------------------------------------------- |:---------------------------------------------------------------------------------- |
| `user_account` / `user_password`                    | 直接就是凭据，必须换掉（HAR 里有两处：URL 查询串、`queryString` 数组的 `"value"`） |
| `wlan_user_mac` / `wlan_user_ip` / `wlan_user_ipv6` | XOR 混淆，可还原 → 等价于明文的本机 MAC / IP                                       |
| `wlan_ac_ip` / `program_index` / `page_index`       | 同样是 XOR 混淆；属服务端标识，风险低但可一并替换                                  |

## 🔍 当初这些抓包证明了什么

以下结论来自对上述 5 份抓包的逐条核对（原始值已随文件删除，可自行重抓复核）：

1. **成功与失败成对出现**：先 `dr1003({"result":0,"msg":"密码错误","ret_code":1})`，改正密码后
   再来一次就是成功；`callback` 在同一会话内**递增**，响应回显同一个 callback 名。
   → 说明**成功与失败走的是同一套接口与参数**，唯一差别是密码对不对。
2. **`result:1` 只代表协议层成功**：同一套接口既会回"密码错误"也会回"认证成功"，
   所以**必须再做一次真实联网校验**才能判定登录成功（这正是本项目防"伪登录"的做法）。
3. **XOR key 随客户端 IP 变化**：同一会话内 key 恒定，换网段就换 key
   （有线实测 `0x20`、WiFi 2.4G 实测 `0x25`、WiFi 5G 实测 `0x29`）。
   四份抓包覆盖**两种介质 + 三种 key**，正好用来验证"key 由本机 IP 推导"。
4. **认证是单次 GET，没有多轮挑战**：全程只有一个客户端的单次会话，不需要任何 Cookie，
   所有参数都在一条 GET 请求里（这也是为什么它天然怕抓包）。
